## Task 1: 移除 Attributes 类的死锁冗余代码

**Objective:** 移除 `Attributes` 类中从未使用的 `ReadWriteLock`/`Lock` 及相关导入，消除误导性代码。

**背景:** `Attributes` 的 `ReadWriteLock` 仅包裹了 `put()` 方法（`writeLock.lock()` → `map.put()` → `writeLock.unlock()`），但所有读操作（`getAttribute`、`getAttributes`、`containsColumn`、`values`、`size`、`columns`）直接访问 `LinkedHashMap` 而未加读锁。

实际上 `Attributes` 实例仅在 `ClassMeta` 构造时通过 `LinkedHashMap` 赋值一次，运行时从未被修改（`put()` 在外部无任何调用路径）。因此 `ReadWriteLock` 是完完全全的死代码，且会误导维护者认为此类是线程安全的。

**影响文件:**
- Modify: `orm/src/main/java/.../meta/schema/Attributes.java`

**Step 1: 确认锁无实际用途**

验证 `put()` 的调用来源：

```bash
grep -rn "\.put(" orm/src/main/java/work/myfavs/framework/orm/meta/schema/Attributes.java --include="*.java"
```
Expected: 只在 `put()` 方法体内和测试中有引用，无生产调用。

**Step 2: 移除死锁代码**

将:
```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReadWriteLock;
import java.util.concurrent.locks.ReentrantReadWriteLock;

...

  private final Map<String /* columnName */, Attribute> map = new LinkedHashMap<>();

  private final ReadWriteLock readWriteLock = new ReentrantReadWriteLock();
  private final Lock          writeLock     = readWriteLock.writeLock();
```

改为:
```java
  private final Map<String /* columnName */, Attribute> map = new LinkedHashMap<>();
```

**Step 3: 精简 put() 方法**

将 `put()` 从 8 行（含 `writeLock.lock()/unlock()`）简化为 2 行：

```java
  public Attribute put(String columnName, Attribute value) {
    if (StringUtil.isEmpty(columnName))
      throw new InvalidDataAccessException("数据库字段名不能为空! ");
    Objects.requireNonNull(value);
    return map.put(columnName.toUpperCase(), value);
  }
```

**Step 4: 移除未使用的 import**

最终 `Attributes.java` 的 import 从当前 8 行简化为 5 行：

```java
import java.util.*;
```

（只需保留 `import work.myfavs.framework.orm.util.common.ArrayUtil;`、`import work.myfavs.framework.orm.util.common.StringUtil;`、`import work.myfavs.framework.orm.util.exception.InvalidDataAccessException;`、`import java.util.*;`、`import java.util.function.BiConsumer;`）

不再需要：
- `java.util.concurrent.locks.Lock`
- `java.util.concurrent.locks.ReadWriteLock`
- `java.util.concurrent.locks.ReentrantReadWriteLock`

**Step 5: 运行测试确认无回归**

```bash
mvn test -pl orm
```
Expected: 305/305 通过，0 失败
